\section{Experimental Protocol}
\label{sec:experiments}

The evaluation protocol is organized around the claim types that ClaimBench is intended to control. It does not attempt to outperform specialized systems on their own leaderboards. Instead, it tests whether the framework blocks unsupported claims, reports uncertainty, separates evidence dimensions, and produces reproducible artifacts.

The first group of experiments uses synthetic known-truth cases. These cases define explicit combinations of evidence dimensions and expected claim outcomes. They are used to verify the semantics of the non-compensatory gate. The purpose is not to approximate a real scientific domain, but to check that supported, unsupported, and uncertain cases are handled consistently under controlled conditions.

The synthetic design evaluates 144 controlled configurations. These configurations vary support for prediction, topology, direction, causal interpretation, uncertainty, and release reproducibility. The expected outcome is fixed by the claim contract, not by model performance. The strongest acceptance criterion is therefore absence of unsupported supported claims. This is stricter than checking aggregate accuracy because a single false authorization of a causal or mechanistic statement can be more damaging than several conservative abstentions.

The second group uses external benchmarks. SciFact provides a real scientific claim-verification setting with support, contradiction, and not-enough-information labels. ClaimBench evaluates a transparent local retrieval and rationale baseline, then reports the extent to which shortcut evidence would create overclaiming risk. The Tuebingen cause-effect benchmark provides pairwise cause-effect data. ClaimBench evaluates transparent direction controls and quantifies how many causal direction claims would be unsupported if correlation were treated as sufficient evidence.

The external controls are intentionally not optimized for leaderboard performance. In SciFact, the objective is to separate evidence retrieval from support authorization. A high retrieval score can still leave support uncertain, and a lexical shortcut can still overclaim. In the Tuebingen benchmark, the objective is to demonstrate that correlation-only direction is not sufficient for causal wording. The benchmark therefore functions as an overclaiming stress test. This is closer to the intended DSS role than to conventional predictive modelling.

The third group evaluates the writing and release workflow. The manuscript claim audit checks whether active project texts contain wording that violates executable claim boundaries. The LLM claim extraction audit checks whether candidate extraction can be included without making the LLM authoritative. The reproduction manifest executes the full v2 pipeline and records stage-level outcomes. The release check verifies that required artifacts are present, non-dirty, and aligned with expected decisions.

The fourth group evaluates component necessity. Each ablation removes or weakens one decision-support component and then observes whether unsupported wording becomes possible. The tested removals include replacing the gate with a correlation-only evaluation, replacing it with a weighted score, removing topology and direction blocks, forcing uncertainty into binary decisions, using lexical citation overlap as a shortcut, allowing correlation to authorize causal direction, and removing manuscript auditing. This makes the experiment more informative than a pass or fail release check because it shows why the system needs each component.

The protocol was also designed to avoid circular evidence. The synthetic cases check whether the rules behave as specified. The external benchmarks test whether the same rules expose known risks outside the original neurocomputational setting. The manuscript audit then evaluates whether the writing respects the same limits. Finally, the release check confirms that the package being described is the package that can actually be inspected. This order matters because the paper would be weaker if it only reported a clean manuscript audit without external stress tests, or if it only reported external tests without checking the manuscript itself.

The evaluation also records the limits of the results. The SciFact adapter is transparent but not competitive. The Tuebingen controls are diagnostic but not presented as a causal-discovery system. The LLM layer is interface-level evidence and not a benchmark of commercial LLMs. The ablation is designed to expose specific risks rather than to estimate a universal false-positive rate. These limits are part of the experimental protocol because they prevent the experiments from becoming new sources of overclaiming.

All reported numerical artifacts were generated before this manuscript draft. This draft does not manually edit JSON result files and does not regenerate numerical outcomes. The reported release artifact indicates a clean v2 package with no missing, dirty, or failing required artifacts.
