\section{Method}
\label{sec:method}

The method is designed as a decision-support process rather than as a predictive model. The user of the system is assumed to be an author, reviewer, or research team that has a manuscript draft, a set of computational artifacts, and a set of claims that may be too strong for the available evidence. ClaimBench receives those elements and returns an explicit audit decision for each claim class. The workflow is summarized in Fig.~\ref{fig:claimbench-workflow}.

ClaimBench represents a scientific statement as a claim contract. A contract defines the type of claim, the evidence dimensions required to support it, and the conditions under which the claim must be blocked or marked uncertain. The current framework distinguishes predictive, reproducibility, topology-specific, directed, causal, mechanistic, structure-function, digital-twin, and state-of-the-art claims. This taxonomy is intentionally practical. It is designed to capture common overclaiming patterns in AI and neurocomputational papers rather than to provide a philosophical theory of scientific explanation.

Each claim type has a non-compensatory evidence gate. This means that missing evidence in a required dimension cannot be offset by strong evidence in another dimension. For example, high predictive correlation does not authorize a causal claim. A reproducible analysis does not authorize a mechanistic claim if topology and direction are absent. A local observational association does not authorize a whole-brain digital-twin statement. The decision can be supported, blocked, or uncertain. The uncertain state is important because borderline cases should not be forced into support or rejection when stability is insufficient.

The non-compensatory design is stricter than a weighted score. This is deliberate. Weighted scoring is useful for ranking models, but it can hide the exact missing assumption that makes a scientific statement invalid. ClaimBench keeps this information visible by separating criteria and by producing decision artifacts that can be inspected by authors and reviewers.

The framework separates evidence into operational dimensions. Prediction measures whether a model improves output agreement with observations. Reproducibility checks whether artifacts can be regenerated from a clean repository state. Topology specificity checks whether the claim depends on the correct structural relation rather than on a generic control. Direction checks whether the ordered relation is supported. Causality checks whether the evidence is sufficient for causal wording. Structure-function association checks whether anatomical and functional descriptors are linked under appropriate controls. Cost and fidelity summarize whether stronger claims require disproportionate computational burden.

These dimensions are not assumed to be independent in the biological sense. They are separated for auditability. The goal is to prevent a manuscript from using one evidence dimension as a substitute for another. This separation is also useful for review response because it makes the claim boundary explicit. A reviewer can disagree with a threshold, but the repository shows which claim depends on that threshold and which artifact implements it.

The decision-support interpretation is important. ClaimBench does not decide whether a research direction is valuable, and it does not replace expert judgement. It provides a structured answer to a narrower question: given the artifacts currently present in the repository, what classes of claims can be defended without overclaiming? This makes the output closer to an executable methodological checklist than to a conventional score. The checklist is executable because each decision points to an artifact, and it is methodological because the artifact is interpreted under a predefined claim boundary.

Operationally, each claim contract contains four elements. The first element is the claim family, for example prediction, mechanism, causality, reproducibility, or digital-twin scope. The second element is the required evidence vector. The third element is the blocking rule that defines which missing evidence dimensions prevent authorization. The fourth element is the decision record, which includes the artifact path, the observed evidence, the allowed wording, and the forbidden wording. This structure makes the framework useful for manuscript revision because a blocked claim is not only rejected. It is accompanied by the reason for rejection and by the weaker claim that remains admissible.

The LLM layer is designed as a candidate extractor, not as a judge. In the current release, the default mode is deterministic. It scans manuscript text and extracts sentences that match conservative claim patterns related to mechanism, prediction, causality, digital twins, reproducibility, generalization, and state-of-the-art language. An optional environment variable can point to a local JSON file containing candidate claims generated by an external LLM. The framework then records that candidates came from an external file, but the final authorization remains controlled by the same executable gates.

This design avoids a common failure mode in LLM-assisted science. If an LLM is allowed to decide that a claim is supported, the audit becomes dependent on an opaque and potentially changing model. ClaimBench instead treats LLM output as untrusted input. It can increase coverage by pointing the auditor to statements that deserve checking, but it cannot turn unsupported evidence into a supported claim. The current artifact explicitly records that no LLM API was called and that the LLM layer was non-authoritative.

The current implementation deliberately uses a deterministic fallback as the reproducible baseline. This does not claim that the fallback is linguistically superior to modern LLMs. It fixes the audit boundary. Future LLM outputs can be loaded into the same interface, but they will still be evaluated as candidate-generating inputs. This design is important for DSS-oriented reproducibility because the decision policy remains stable even if the claim-discovery interface evolves.

ClaimBench includes external controls to avoid validating only on synthetic cases. SciFact is used to evaluate claim-evidence handling in a scientific text setting. The framework reports label counts, retrieval performance, overclaiming risk, confidence indicators, and abstention. The result is interpreted as evidence that the audit can operate on a real scientific claim benchmark, not as evidence of state-of-the-art SciFact performance.

The Tuebingen cause-effect benchmark is used to test causal wording control. Transparent directional methods are evaluated, but the primary question is whether correlation-only evidence would incorrectly authorize causal direction. This framing is important. A weak causal-direction baseline can still be valuable if it exposes why causal claims must be blocked under insufficient evidence.

The framework includes component ablations to test whether each part has non-redundant value. Removing the non-compensatory gate, topology block, direction block, uncertainty state, evidence retrieval separation, causal abstention, or manuscript audit reintroduces a specific risk. The threat model then maps those risks to reviewer-facing concerns. It covers rules without value, arbitrary thresholds, synthetic overfitting, causal overclaiming, wording drift, LLM authority drift, and hidden uncertainty.

This part of the method is designed for adversarial review. A reviewer may ask whether ClaimBench is only a collection of rules. The ablation answers that question by showing which unsupported claims become possible when each rule is removed. A reviewer may ask whether the LLM layer creates a new unsupported authority. The threat model answers that question by requiring the LLM layer to remain non-authoritative.

The method therefore combines three layers. The first layer is formal, because claims are mapped to evidence contracts. The second layer is empirical, because synthetic and external controls test whether the contracts block known failure modes. The third layer is editorial, because manuscript wording is audited against the same contracts. The combination is what makes the system a decision-support framework rather than a collection of diagnostic scripts.
